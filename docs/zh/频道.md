# 频道

## 概念科普

### 什么是频道？

**频道（Channel）** 是 JiuwenSwarm 的消息接入层，作为统一的消息中枢，负责连接各种外部聊天平台（如飞书、钉钉、企业微信、Telegram 等）。它实现了以下核心功能：

| 能力 | 说明 |
|------|------|
| **消息接入** | 接收来自不同平台的消息，统一格式后送入 JiuwenSwarm 处理 |
| **多端同步** | 同一套 JiuwenSwarm 服务可同时接入多个平台，消息互通 |
| **身份识别** | 为每个平台的用户建立唯一标识，维护独立的对话上下文 |
| **安全隔离** | 不同频道的消息流相互隔离，支持白名单、权限控制等 |

### 频道、网页对话与智能体的关系

三者构成了 JiuwenSwarm 的完整对话体系，关系如下：

- **频道（Channel）**：消息接入层，负责接收来自不同平台的消息并统一格式。除了飞书、小艺等外部频道，**网页对话（Web UI）本身也是一个内置频道**。
- **智能体（Agent）**：消息处理引擎，所有频道接入的消息最终都由智能体进行理解、推理和响应。
- **网页对话**：内置的 Web 频道，提供可视化界面供用户直接与智能体交互。


### 简介

JiuwenSwarm 的​**频道**​，是您与不同聊天平台对话的**渠道**。JiuwenSwarm 已经实现了**鸿蒙小艺、飞书**等 channel 的无缝接入，并持续拓展至更多元渠道。可以直接通过 **飞书**、**鸿蒙生态终端的小艺 app** 与 JiuwenSwarm 对话。

### 数字分身

JiuwenSwarm 在**飞书**和**企业微信**频道中支持**群聊数字分身**功能。开启后，机器人将在群聊中作为指定用户的"数字分身"运作——自动识别群聊中与该用户相关的消息并代为回复，以该用户的第一人称口吻进行对话。对于待办、提醒等个人行动类回复，数字分身会自动私发给用户本人，同时在群内补发一条简短确认。无关消息则自动过滤，不消耗 Agent 资源。

该功能默认关闭，开启方式详见下方各频道的配置说明。

### 配置方式

本教程以**网页端配置**为主，后续各频道的接入说明均基于网页操作演示。

如需手动配置，可编辑 `config.yaml` 文件（默认路径：`~/.jiuwenswarm/config/config.yaml`），将对应频道设为 `enabled: true` 并填写鉴权信息，保存后自动重载。

### 频道特性差异

不同频道在私聊/群聊支持、触发方式、权限要求等方面存在差异：

| 特性 | 说明 |
|------|------|
| **私聊/群聊** | 部分频道仅支持私聊（如小艺），部分同时支持私聊和群聊（如飞书、企业微信） |
| **触发方式** | 私聊中通常直接对话即可触发；群聊中可能需要 @机器人或使用特定指令前缀 |
| **权限要求** | 不同平台对机器人权限的要求不同，如消息读取权限、群管理权限等 |

具体差异请参考各频道的详细接入说明。

| 接入方式 | 说明 |
|----------|------|

### Web URL 附件

WebChannel 保留 `chat.send` 的旧版 URL 附件格式，例如：

```json
{
  "type": "req",
  "id": "chat-with-attachment",
  "method": "chat.send",
  "params": {
    "content": "请查看附件",
    "files": [{"name": "报表.xlsx", "url": "https://files.example/report.xlsx?signature=..."}]
  }
}
```

`uri` / `filename` 仍可作为 `url` / `name` 的别名。此下载入口仅用于 `chat.send`；
其他方法携带列表形式的 URL 附件会被拒绝，不会触发网络或文件写入。
当前 Web 图片、文档上传仍走 `media.persist` / `document.persist`，持久化后的
`files.uploaded_images` / `files.uploaded_documents` 以及已有本地 `path` 引用不走 URL 下载，行为不变。

#### 公网与内网来源

HTTP、HTTPS 公网附件无需增加白名单，支持自定义端口、签名路径和查询参数，以及最多 5 次正常重定向。
URL 长度上限为 16384 个字符，不允许嵌入用户名／密码或包含原始空白、控制字符。
每一跳都重新检查目标；连接直接使用通过校验的 DNS 解析结果，不先检查一次再让 HTTP 客户端重新解析。
域名的任一解析结果不符合策略时拒绝整个下载，覆盖 IPv4、IPv6 和 IPv4 映射地址。
非标准十进制／短格式／八进制数字 IP 被拒绝，不能绕过解析器检查。

默认拒绝内网和回环地址。确有内网附件服务时，由管理员在 **Gateway 进程环境**中设置
`WEB_ATTACHMENT_PRIVATE_ORIGINS`，随后重启 Gateway，例如：

```powershell
$env:WEB_ATTACHMENT_PRIVATE_ORIGINS = "https://files.corp.example:8443,http://10.20.30.40:8080"
```

Linux / 容器环境：

```bash
export WEB_ATTACHMENT_PRIVATE_ORIGINS="https://files.corp.example:8443,http://10.20.30.40:8080"
# 使用现有方式启动 Gateway；只在前端或 Agent 沙箱中设置该变量不会生效。
```

白名单仅为内网下载增加例外，不限制原有公网下载。它精确匹配协议、主机和有效端口，支持 IDNA 域名
和 IPv6，例如 `http://[fd12::10]:8080`；不支持通配符、域名后缀规则、URL 用户信息、路径、查询、片段或
末尾 `/`。省略端口时分别为 HTTP 80、HTTPS 443。域名按 DNS 语义规范化，不能用子域名或其他端口替代。
配置表示信任该服务及其 DNS，应仅填写受控的专用文件服务。

元数据服务已知地址（含链路本地地址）、组播、未指定及保留地址、IPv6 转换等特殊范围始终禁止，
白名单不能放开这些地址；即使同一白名单域名通过重定向或后续 DNS 解析转到这些地址也会被拒绝。
下载不继承环境代理，不携带浏览器 Cookie、会话凭据或客户端 Authorization。

#### 安全落盘与资源限制

下载文件保存到当前 Agent 工作区的 `attachments/<服务端随机ID>/<文件名>`。
正常文件名、中文名、空格和扩展名保留，同名附件互不覆盖。禁止路径分隔符、盘符、UNC、Windows ADS、
设备名、控制字符等；目录符号链接／Windows 目录联接不会被跟随。Windows 写入期间锁定父目录以防替换，
Linux 使用目录 FD、`O_NOFOLLOW` 和独占创建约束写入。
Windows 新目录继承工作区 ACL，保留沙箱账户已有的工作区读取权限，不创建会丢失该权限的私有 DACL。

成功后，传给 Agent 的附件 `path`、`filename` 和 `size_bytes` 由网关生成，移除原始 `url` / `uri`
及可覆盖本地路径的别名，不让下游再次下载原始 URL。空文件也是有效附件。
若任一附件被拒绝、下载或保存失败，当前请求返回错误，不进入 Agent，也不转发未校验 URL；
本请求此前已保存的附件会被清理。取消下载同样清理未完成请求的落盘文件。

| Gateway 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `WEB_ATTACHMENT_PRIVATE_ORIGINS` | 空 | 逗号分隔的精确内网来源白名单 |
| `WEB_ATTACHMENT_MAX_BYTES` | `67108864`（64 MiB） | 每个下载附件的最大字节数，检查声明长度及实际解压后的流量 |
| `WEB_ATTACHMENT_TIMEOUT_SECONDS` | `60` | 每个附件下载的总超时，包含 DNS、连接、响应读取和全部跳转 |
| `WEB_ATTACHMENT_MAX_FILES` | `16` | 每个 `chat.send` 中 URL 附件的最大数量，不计已持久化本地引用 |

网关最多同时下载 4 个附件；单次连接和读取还分别受不超过 15 秒、30 秒的阶段超时约束。
三个资源限制必须为正整数；非法配置阻止 WebChannel 初始化，不退回不受限模式。
大附件或慢速文件服务可以显式调整限制，设置后重启 Gateway。

错误响应使用既有 WebSocket `res` 格式，`ok: false`，附带 `code` 和可读 `error`。
错误码包括 `ATTACHMENT_REJECTED`、`ATTACHMENT_INVALID_NAME`、`ATTACHMENT_TOO_MANY_FILES`、
`ATTACHMENT_TOO_LARGE`、`ATTACHMENT_DOWNLOAD_FAILED`、`ATTACHMENT_SAVE_FAILED`。
日志仅记录拒绝码，不打印含凭据或签名参数的下载 URL。

升级时，原先依赖任意内网 URL 下载的客户端需要配置具体文件服务白名单；
客户端应使用网关返回／转交的 `path`，不要假定附件仍落在工作区根目录或同名文件会被覆盖。
这些限制仅作用于 WebChannel 的旧版 URL 下载入口，不替代 Agent 工具自身的网络和文件权限策略。

在仓库根目录运行回归：

```bash
python -m pytest tests/unit_tests/channel/test_web_attachment_security.py tests/unit_tests/channel/test_web_attachment_storage.py -o addopts= --asyncio-mode=auto -q
```

测试使用模拟响应及本机临时 HTTP 服务，不访问公网或元数据服务；
Windows 原生覆盖目录联接、目录替换和长路径，Linux 专用目录 FD 竞态测试需在 Linux 上运行。
源码回归不能替代部署后的公网文件、CDN 跳转、内网白名单及实际上传验收。

### SSH

SSH 入口由 `channels.ssh` 控制，要求 `gateway.agent_client.type: agentos_router`，并安装可选依赖：

```bash
pip install "jiuwenswarm[ssh]"
```

内置配置默认 `enabled: false`，不创建 SSH 监听；默认地址为 `127.0.0.1:2222`。服务器可以显式改为网卡地址或 `0.0.0.0`，所有监听地址均执行相同的公钥认证。

#### 配置授权公钥

客户端生成密钥对，例如：

```bash
ssh-keygen -t ed25519 -f ./alice_agent_key -C alice
```

由管理员将 `alice_agent_key.pub` 的内容写入**网关主机**上的 `/etc/jiuwenswarm/ssh/alice_authorized_keys`，私钥保留在客户端。该文件使用 OpenSSH `authorized_keys` 格式，每行一个公钥，可包含多个授权公钥；网关进程需要有读取权限。

将下面配置合并到当前实例的 `config.yaml`，保留已有的 AgentOS 后端连接参数：

```yaml
gateway:
  agent_client:
    type: agentos_router
channels:
  ssh:
    enabled: true
    listen_host: "127.0.0.1"
    listen_port: 2222
    host_key_path: ~/.jiuwenswarm/config/ssh_host_key
    authorized_keys:
      alice: /etc/jiuwenswarm/ssh/alice_authorized_keys
    relay_timeout_sec: 3600
```

`authorized_keys` 的键是允许登录的 SSH 用户名，值是该用户在网关主机上的授权文件路径，支持 `~` 展开。请为每个用户单独配置：登录用户名会作为 `ssh.relay` 的 `user_id` 传给 AgentOS。一个用户的密钥不能用于另一个未授权的用户名。

对外提供服务时按需修改 `listen_host`。若监听 `0.0.0.0`，可设置 `advertise_host` 为客户端可达的真实 IP 或主机名，用于返回给客户端；客户端连接真实地址。元戎部署的实例路径和模板说明见[部署文档](../../deploy/yuanrong/README.md#ssh-入口认证)。

#### 认证与升级行为

- 密码和键盘交互认证已禁用；任意密码、空凭据、未知用户和未授权公钥均被拒绝。
- AsyncSSH 校验该用户名的授权公钥及对应私钥签名，并执行授权文件中的 `from` 等限制；校验失败后不再由回调放行。
- 启用 SSH 但 `authorized_keys` 未配置、文件不存在、不可读或没有有效条目时，SSH 通道启动失败，不开放监听端口。日志会提示检查授权配置或文件。
- 从旧版本升级后，必须配置授权公钥才能继续使用 SSH；不再接受任意密码或公钥。未启用的通道不受影响。
- 授权文件在通道启动时读取。修改或撤销公钥后需重启 SSH 通道或 Gateway；撤销授权时还应断开该用户已建立的连接。

`host_key_path` 是网关向客户端证明身份的服务端密钥。`gateway.agentos.ssh.client_keys_dir` 则是网关连接后端 YuanRong 的南向私钥目录。二者均不能替代 `channels.ssh.authorized_keys` 的入站用户认证。

#### 连接与验证

```bash
ssh -o IdentitiesOnly=yes -i ./alice_agent_key -p 2222 alice@<gateway-host>
```

认证成功后，通过 `ssh.relay` 中继到 AgentOS / 沙箱。交互式连接需先通过 `3rdagent.switch` 选择具有沙箱的 Agent；尚未切换或当前为内置 Agent 时，可通过 SSH 远程命令首词选择 `agent_type`。后端配置决定中继是否可用。

部署验收时，确认已授权用户可以连接；再使用未授权私钥、错误用户名和下面的密码登录方式，均应收到认证拒绝，且不触发 `ssh.relay`：

```bash
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password -p 2222 alice@<gateway-host>
```

设置 `enabled: false` 后确认服务不再监听该 SSH 端口。本地回归见 `tests/unit_tests/channel/test_ssh_auth.py`，覆盖真实 SSH 握手及未授权请求无法进入中继的行为；部署环境仍需按上述步骤独立验收。
